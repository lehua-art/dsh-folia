# 站点资源"先下载到本地，再本地渲染" + 批量下载

> 用户定的产品流程（2026-10-30）：
>
> 1. 用户装好插件后，**开机动画 / 壁纸 / 桌宠 / 皮肤包** 一律**先从站点下载到本地**；
> 2. 渲染方（我们的插件、皮肤中心）**只从本地取数据**，不再边播边拉远端；
> 3. 站点列表支持**一次勾选很多个并发下载**，不是点一个下一个。
>
> 本文件是这件事的落地设计。`docs/refactor-pending/download-queue.js` 是已经写好的队列骨架
> （并发上限 / 断点续传 / 幂等去重 / 原子完成 / 持久化），下一版接线后移入 `lib/`。

---

## 一、现状盘点（哪些已经满足、哪些不满足）

| 资源 | 现状 | 差什么 |
|---|---|---|
| 皮肤包 | ✅ 已经是"下载 zip → 解到 `$DSH_HOME/skins` → 皮肤中心从本地读" | 只差**批量**（当前一次一个） |
| 开机动画 | ✅ `/boot/download` 已有"下载一条到本地"，客户端从本地播 | 只差**批量** + 进度可见 |
| 桌宠 | ✅ `/pets/install` 下载 zip 解到本地目录 | 只差**批量** |
| 壁纸（本机） | ✅ 本地扫描，天然本地渲染 | — |
| **壁纸（站点）** | ❌ **直接流远端**（`media` 是站点绝对 URL，浏览器边下边播） | 要改成"先下到本地库 → 播本地文件" |

结论：**主要工作量在站点壁纸**，其余三种只是把"逐个动作"升级成"批量队列 + 进度"。

## 二、目标架构

```
站点清单（category=wallpaper|boot-animation|desktop-pet|assistant-skin）
        │  用户勾选 N 个
        ▼
POST /folia/downloads/add   { items: [{ kind, url }] }        ← 批量入队
        │
   download-queue.js（lib/，并发默认 3）
        │  每个 job：<dest>.part → 完成 rename → job.done
        │  并发 3：弱网下同时开十几个连接会让"每个都慢、都不完成"
        ▼
$DSH_HOME/library/<kind>/<sha256(url)[:32]>.<ext>            ← 本地库（唯一真源）
        │
        ├─ 壁纸：inventory 合并时，命中库的条目 media 改成本地路由
        │        `/folia/local-media/<id>`（Range/HEAD 复用 lib/serve.js）
        ├─ 开机动画：boot 清单优先列本地已有
        ├─ 桌宠：本地目录（已是现状）
        └─ 皮肤包：`$DSH_HOME/skins/<id>`（已是现状）
```

**渲染方永远只看到本地路径** —— 这是我们与皮肤中心/播放器的共同前提。

## 三、接口（新增）

| 方法 | 路径 | 语义 |
|---|---|---|
| POST | `/folia/downloads/add` | `{items:[{kind,url}]}` 批量入队，返回每个 item 的 `{id, status, existed}` |
| GET | `/folia/downloads/list` | 全部 job 快照（状态/进度/失败原因），UI 轮询或 SSE |
| POST | `/folia/downloads/cancel` | `{id}` 取消（在途会 abort，保留 `.part` 供续传） |
| POST | `/folia/downloads/retry` | `{id}` 重试（失败项） |
| GET | `/folia/local-media/<id>` | 本地库字节（Range/HEAD），替换原来的远端 `media` URL |

判据（每条都要有负对照）：

1. **并发上限**：入队 10 个，同时在跑的 ≤ 3（其余排队）。
2. **幂等**：同一 URL 入队两次 ⇒ 只有一个 job（第二次返回 `existed: true`）。
3. **续传**：删掉 `.part` 后一半再入队 ⇒ 从已有字节续，不重头。
4. **原子**：中断/取消后 `dest` **不存在**，只有 `.part`；完成后 `.part` 消失。
5. **可失败**：单个 404 只让该 job `failed`，队列继续跑其它。
6. **本地优先**：库里有文件 ⇒ inventory 的 `media` 指向 `/folia/local-media/<id>`，`local: true`。

## 四、界面（客户端）

```
① 壁纸 / 开机动画 / 桌宠 / 皮肤包四个站点列表统一加：勾选框 + 「下载选中（N）」
   · 已有本地文件的条目显示「已在本地」，勾选框默认不选
   · 底部固定一行进度：`下载中 2/7 · 鲸鱼娘望海 43% · 1.2 MB/s`
② 单击某条仍可直接用：若未下载 ⇒ 自动入队并在完成后自动应用（用户不必等）
③ 失败条目显示原因 + 「重试」，不做"静默失败"
```

## 五、迁移与兼容

```
· 老版本直接播放远端 URL 的路径**保留为兜底**：本地无文件且用户点了"立即播放（不下载）"
· 已有缓存（4.14+ 的 site-media 缓存）可直接迁进 library（同一份字节，换目录即可）
· 磁盘上限：library 与 site-media 共用 2 GiB（DSH_FOLIA_SITE_CACHE_MB），LRU 按 atime
```

## 六、实施顺序（每步可独立发布）

| 步 | 内容 | 用户感知 |
|---|---|---|
| 1 | 队列接线（`lib/download-queue.js`）+ `downloads/*` 接口 + 判据 | 无界面，但批量接口可用 |

| 5 | 弱网优化：站点侧低码率变体 / 本机 ffmpeg 生成 1080p 副本并优先播 | 4K 弱网也能用 |
