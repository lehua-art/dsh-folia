# 下载 / 安装状态机（防复发清单）

> 这一页存在的唯一原因：**同一个故障形态连续发生了三次**。
> 4.23.3「切页签进度消失」→ 4.23.4「点了没反应」→ 4.23.5「下载完成了但没落地」，
> 每次都是用户先撞上、我再补一个格子。共同的根因不是某一行代码，而是"卡片此刻该显示什么、
> 能不能点、等多久算失败"这件事**从来没有一张完整的表**。
>
> 所以这里把表写死，并用 `test/verify-install-flow.mjs` 逐行钉住（A1–A14 / E1–E4）。
> **改状态机 ⇒ 这张表、那页判据、CHANGELOG 必须一起改**，否则 `verify-install-flow.mjs` 会红。

状态机的唯一实现：`src/local-first.js` 的 `dlCardState()`（四个模块共用：皮肤 / 开机动画 / 桌宠 / 壁纸）。
面板只负责"喂输入"（job、是否已装、点击时刻）和"按 `disabled` / `retry` 渲染按钮"。

---

## 1. 七个状态与展示

| 状态 | 触发条件（输入） | 按钮文案 | 明细行 | 可点 | 用例 |
|---|---|---|---|---|---|
| `idle` | 没有 job、未安装、没有失败记录 | 安装 | — | ✅ | **A1** |
| `submitting` | 本卡片有点击记录（`sub.begin` 写入）且还没有 job | 正在提交… | 已等待 N 秒（≥3 秒才显示） | ❌ | **A2**、**A13** |
| `queued` | job 存在且 `status=queued` | 排队中：前面还有 N 个 | 同左 | ❌ | **A3** |
| `running` | job `status=running` | 下载中… x% | `a/b MB · 约剩 N 秒`（样本不足不给秒数） | ❌ | **A4**、**A14** |
| `installing` | job `status=done` 且本机未落地，且**未超过落地上界** | 解压/落位中… | — | ❌ | **A5**、**E2** |
| `done` | 本机已落地（`installed=true` 或 `cards.markOk()`） | 本模块自己的词（已安装 / 使用中） | — | 安装按钮置灰；页签另给「应用」 | **A7**、**E1**、**E2** |
| `failed` | 见下面第 3 节的**每一种失败码** | 重试 | 原因：<人话> | ✅ | **A6**、**A8**、**A11**、**A12**、**E3**、**E4** |

判定顺序（就是"为什么这张卡片显示这个"）：`queued` → `running` → **本卡片的明确失败** →
`submitting` → **done 但未落地** → `done` → job 自身失败 → `idle`。

> 为什么"本卡片的明确失败"排在"done 但没落地"**之前**：自动补装失败（宿主回 `no-skin-json`）
> 如果被 `installing` 盖住，卡片就继续显示「解压/落位中…」——**失败又变静默**，那正是用户抱怨的东西。
> 反过来"点了就清掉旧失败"（`cards.begin()`）与"成功即 `done`"（`cards.markOk()`）保证它不会盖住正常路径。

## 2. 两条超时（缺一条就会留下一种"永久转圈"）

| 场景 | 判据 | 默认 | 覆盖 | 结果 | 用例 |
|---|---|---|---|---|---|
| 包下完了但**落地**没发生、也没人再推进它 | 从本卡片**第一次被观察到"done 但未落地"**起算 | **90000 ms（90 秒）** | `DSH_FOLIA_INSTALL_STALL_MS`（夹取 **5000（5 秒）..1800000（30 分钟）**；非法/缺省回落 90 秒） | `failed` +「重试」，原因「下载已完成但安装未落地，点「重试」」 | **A5 / A6** |
| 等的那条 **jobId 从 `/downloads/list` 里消失**（宿主重启 / 队列被重置 / job 被清理） | **连续 5 次**都查不到（5 × 1.5s ≈ **7.5 秒**） | 5 次 | 常量 `DL_JOB_MISS_LIMIT` | `failed` +「重试」，原因「下载任务已丢失，点「重试」」 | **A8 / E3** |
| 同一个 id **正在装**（两条安装路径撞上） | 宿主栅栏 `installGateTry()` | TTL **2 分钟** | 常量 `INSTALL_GATE_TTL_MS` | `{ok:true,pending:true,deduped:true}`，**不重复解压** | **A15 / A17** |

两条判据的补充口径：

- **只数"成功拿到列表但没有这条 job"**：`/downloads/list` 自己请求失败**不算**查不到
  （网络抖动不等于任务丢失）。查到一次（哪怕还在跑）⇒ 连续计数清零。
- 判 `failed` 之前**先回列表核一次 `installed`**：`/skins/list`、`/boot/list`、`/pets/list` 的
  "已装"是唯一真源。装好了就直接当成功（`done`），不要因为"我们等的那条 job 没了"而误报失败。
  用例：**A9**。
- 浏览器里没有 `process.env` ⇒ 窗口由**宿主**解析，随 `/folia/downloads/list` 的
  `installStallMs` 字段下发；客户端只用这个数字（拿不到时回落同一个 90 秒常量）。

## 3. 失败码 → 用户看到的那句话

| 码 | 用户看到 | 用例 |
|---|---|---|
| `http-404` | 站点上没有这个文件（404，可能正在补传/已被删除） | **A11** |
| `fetch failed` / `network` | 连不上站点（网络中断或 DNS/TLS 失败） | **A12** |
| `http-500/502/503` | 站点服务器/网关错误，不是本地问题 | **E4** |
| `install-stalled` | 下载已完成但安装未落地，点「重试」 | A6 |
| `job-lost` | 下载任务已丢失，点「重试」 | A8 / E3 |
| `bad-zip` / `not-a-zip` / `no-skin-json` / `bad-skin-json` | 包结构不对：…（各自一句） | — |
| `size-mismatch:…` | 校验失败（字节数与站点声明的长度不一致，点「重试」会续传） | — |
| `submit-timeout` | 超时：请求 150 秒没有返回，点「重试」再发一次 | — |
| `queue-failed` | 下载队列起不来（宿主侧异常），重启 DSH 后再试 | — |

**纪律**：未登记的错误码也必须带出码本身（`下载/安装失败：<code>`），**禁止回落成裸 `failed`**。

## 4. 挂载自愈（用户什么都不点也要能修好）

面板挂载时按"队列状态 + 本地是否已装"做三件事，**同一 id 每次会话只自动尝试一次**
（`LF_HEAL_TRIED`，页面级；用户手动点「重试」不受此限）：

| 情形 | 动作 | 幂等机制 | 用例 |
|---|---|---|---|
| job `done` 但本机未落地 | POST 一次收尾接口：皮肤 `/folia/skins/install`、开机动画 `/folia/boot/download`、桌宠 `/folia/pets/install` | 三者都先看本地文件/缓存：已有 → `exists:true`；否则读 `cache/*-zip/`（**不重新下载**） | **E1 / E2** |
| 自愈失败 | `cards.fail(id, code)` ⇒ 卡片红字原因 +「重试」；提示行同一句人话 | — | A11 / A12 |
| 本地没有对应 job（残留的"进行中"） | `cards.settle(id)` 清掉残留痕迹 ⇒ 回落 `idle`、可点安装 | 队列里没有它 ⇒ 它就不在发生 | **A10** |

另外：开机动画 / 桌宠的收尾接口在**已落地时直接回 `exists:true`**，所以面板可以无脑重试。

## 5. 「装了两遍」与「第二遍装完仍停在解压/落位中…」（4.23.6 追加）

真实故障（用户实测，4.23.5）：进度条满了之后**又装了一遍**；而且第二遍装完仍停在「解压/落位中…」。

根因有两条，都不在"某一格文案"上：

1. **两条安装路径互不认识**：同一次点击会打到同一条接口两次 ——
   ① 客户端 202 轮询到 `job === done` 后自己 POST 一次；② 宿主 `scheduleFinishInstall()` 下完自调用一次。
   两次都会"解压 + 规范化清单 + `rmSync` 掉目录重写"，于是第二次把刚装好的目录删了重来。
2. **"装没装"比错了名字**：站点 catalog id、`skin.json` 里的 id、磁盘目录名**三者不总相同**
   （撞名时上传工具会加 `skin-` 前缀，清单里的 id 还可能被规范化过）⇒ 装好了却判成没装，
   于是又装一遍，且安装成功的响应也没被当成"完成"。

现在的口径：

| 层 | 做法 | 用例 |
|---|---|---|
| 宿主栅栏 | `/skins/install` 在"zip 已就绪 → 写盘完成"这段占 `installGateTry(id)`（内存 Map，TTL **2 分钟**）；命中回 `{ok:true,pending:true,deduped:true}`，**不重复解压**；落位失败立即释放（否则「重试」被自己挡住）；成功标记 `done`（卸载后马上重装不会被挡住）。栅栏**不覆盖下载阶段**（那属于队列，同 URL 幂等）。 | **A15** |
| 客户端先查 | 发安装请求**之前**先查 `/skins/list`：已经装好 ⇒ `markOk` + 刷新，**根本不发请求**。 | **A16 / A18** |
| 成功即 toBe | 任何 `200/2xx`（含 `exists:true`）⇒ `cards.markOk()` **立刻**变「已安装」，不经过 `installing`；并紧跟一次 `load(true)`。 | **A16 / A18** |
| `deduped` | 既不当失败、也不假装完成：保持有上界的当前格（`installing`），刷新清单；若那边已装好就 `markOk`。 | **A17** |
| 归一口径 | `skinInstalledMatch()`：**目录名 / `skin.json.id` / catalog id** 任一命中即已安装（含 `skin-` 前缀归一）。 | **A19** |
| 4xx/5xx | 一律 `failed` + 原因 +「重试」，**不允许**留在 `installing`（明确失败优先于"done 但没落地"）。 | **A20** |

## 6. 端到端判据（真站点替身 + 真宿主路由 + 真下载队列 + 真 zip）

| 编号 | 场景 | 必须看到 |
|---|---|---|
| **E1** | 点击安装一个能在 8 秒内下完的包 | `200` → `skins/<id>/skin.json` 落盘 → `/skins/list` 的 `installed` 有它 → 卡片 `done` |
| **E2** | 点击安装一个**慢包**（body 卡 9 秒） | 宿主先回 **202 + jobId** → 卡片立刻是"排队中/下载中" → `done` → 自动安装 → `installed`；**第二次安装不重新下载** |
| **E3** | 下载中途"宿主重启"（job 表被清空） | 5 次轮询 ≈ **7.5 秒**后 `failed` +「下载任务已丢失」+「重试」可点（不是转圈到 30 分钟） |
| **E4** | 下载中途站点 500 | 立刻 `failed` + 原因 +「重试」可点 |

## 8. 历史（为什么会有这一页）

- **4.23.3**：进度只存在组件本地 state，切页签 = 重新挂载 = 归零 ⇒ 以 `/downloads/list` 为真源。
- **4.23.4**：卡片的"忙"用的是页面级 `busy` ⇒ 别的卡片在装时这张点不动 ⇒ 改成**按卡片**的状态机。
- **4.23.5**：缓存分档（大文件不再双份占盘）。
- **4.23.6**（本页）：
  1. `installing` 加了**落地上界**（90 秒，`DSH_FOLIA_INSTALL_STALL_MS` 可覆盖）——
     根因是收尾只由宿主内存里的 `setTimeout` 推进，DSH 重启就没人做了，而 `jobs.json` 里
     `status=done` 是落了盘的（实测：17,509,106 B 全下完、缓存 zip 完好，但 `skins/rainy-night` 不存在）；
  2. 面板**挂载自愈**：`done` 但未落地 ⇒ 自动补一次（幂等、走缓存），失败把原因写回卡片；
  3. **任务丢失**（jobId 连续 5 次查不到）⇒ `failed` +「重试」，不再无限轮询；
  4. 判失败前**先核 `installed`**；本地没有对应 job 的残留卡片**回落 `idle`**；
  5. 安装成功/失败日志从 `info` 提到 `warn`，带 `id / 耗时 / 结果 / 错误码`（默认终端只出 error+warn）。
