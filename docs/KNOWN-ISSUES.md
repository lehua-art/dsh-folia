# 已知问题（Known Issues）

> 只记**已确诊、已知影响面、尚未修**的问题。每条都给：现象 / 根因 / 影响 / 修法 / 建议排期。
> 已修的进 `CHANGELOG.md`，不进这里。

## KI-1 `verify-client` 关于页 anchor 竞态（4.23.8 发现）

- **现象**：`npm run verify` 在 `test/verify-client.mjs` 第 3 步失败，报
  `AssertionError: 关于页必须包含「项目简介」`，且**整条链短路**（后续步骤不再执行）。
- **根因**：该断言跑在**定时器回调**里（堆栈是 `Timeout._onTimeout`），渲染还没 flush 就断言了；
  抛错又**未被捕获** ⇒ 进程直接崩，所以表现为"退出码 1 + 链短路"，而不是一条可读的红。
- **影响面**：**仅门禁**。产品功能完全不受影响（关于页在真机上正常渲染）。
  在基线 `3915f45` 上**同样失败** —— 与 4.23.8 无关（已用 stash + 重建做过对照实验）。
- **修法**（低风险，两行级）：① 断言前 `await tick()` 让渲染 flush；② 把定时器里的 assert
  包进 `try/catch` 转成 `exit(1)`，让失败可读。
- **建议排期**：单独一个小版（"门禁可信度"），**不要**塞进功能版 —— 它会改变门禁的红绿，
  混在功能版里会让"这次到底是功能坏了还是门禁抖了"无法区分。

## KI-2 i18n 债：41 条漏译 + 242 条孤儿键（4.23.8 发现）

- **现象**：`test/verify-i18n.mjs` 报「零漏译（每个 weT 原文都有词条）」缺 41 条、
  「零孤儿键」多 242 条。
- **根因**：
  - 41 条漏译几乎全是 **4.23.6 / 4.23.7 新增的 UI 文案**（「缓存目录不可写（每次都会重下）」
    「下载超时（已下部分会保留…）」「下载队列起不来（宿主侧异常）」「下载中…（可继续切换皮肤）」…）
    —— 那两版加了文案但没同步英文词表。
  - 242 条孤儿是反向的：词表里留着、**调用点已删或改名**（例如「· 1080p」这种拼接残留）。
- **影响面**：**只影响英文环境**。`weT` 的契约是"没译文就回落原文"（渐进式），
  所以英文用户看到的是**中文原文**，功能与中文环境完全一致，不会崩、不会空白。
  中文用户与中文文案不受任何影响。
- **修法**：补 41 条英文；删/改 242 条孤儿；然后 `test/verify-static.mjs --write-baseline`
  把 ESLint 基线收紧。机械活，但量大，适合单独一版。
- **建议排期**：4.23.10「i18n 对账版」。**不要**塞进功能版 —— 会让 CHANGELOG 的叙事失焦。

## KI-3 4K 解码的硬件边界（4.23.8 记录，非缺陷）

- **现象**：4K60 的 H.264 在部分核显上本身跑不满 60fps，切换时的 200ms 交叉淡化也可能掉帧。
- **影响面**：**浏览器/硬件边界**，不是切换逻辑能修的。4.23.8 起了池化（解码器复用），
  把"新建解码器"的成本消掉了，但**不降低单路 4K 的解码成本**。
- **缓解**：`/folia/diag/switch-stats` 与掉帧提示（rVFC 统计 < 24fps 持续 2s）会建议用户切 1080p。
- **结论**：不修。作为已知边界记录。

## KI-4 `lib/client.js` 是构建产物、不入 Git（4.23.8 记录）

- **现象**：`git show <commit>:lib/client.js` 报 `exists on disk, but not in <commit>`。
- **原因**：它由 `scripts/build-client.mjs` 在 `prepack` 时生成，`.gitignore` 忽略。
- **影响**：想"回退到某一版的客户端"不能靠 git checkout，必须用那个版本的 `src/` 重新 build。
  发布动作必须**先 build 再 pack**（`prepack` 已经自动化了这一步）。
