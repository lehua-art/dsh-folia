# 当天交付协议（Same-Day Delivery）

> 目标：一个功能**当天做完、当天可装、当天可回滚**，不拖成"2–3 天"。
> 适用：本仓（插件）+ 站点仓（folia-admin），两台机器并行。

---

## 1. 拆分规则：一个功能最多 3 步

```
步骤定义（每步必须独立可验证、可回滚）：
  S1 功能骨架（能跑通最小闭环）
  S2 边界与错误（失败路径、限流、降级）
  S3 体验与门禁（UI、文案、测试、发布）
每步 60–90 分钟；超过 90 分钟说明这一步还能再拆。
```

## 2. 每步固定动作（不许跳）

```
1) 改代码（只改这一步范围）
2) node scripts/build-client.mjs            ← 客户端改动必做
3) node test/run-audit.mjs                  ← 0 失败
4) 该功能的 verify（如 verify-pet-chat / verify-pet-settings）
5) 有宿主改动的，跑 test/verify-entry-load.mjs（最小 ctx 加载不抛错）
6) commit + push origin main → 校验 H1==H2
7) 在 PROGRESS 里写一行：步骤 / commit / 结果
```

## 3. 时间盒（参考）

```
09:00–09:20  拆单（写清 3 步 + 判据）
09:20–10:50  S1
10:50–11:00  push + 主机器复核
11:00–12:30  S2
12:30–13:30  午休
13:30–15:00  S3（UI/文案/测试）
15:00–16:00  全量门禁 + 真机安装验证
16:00–16:30  发版（next）
16:30–17:00  用户验收（真机点一遍）
17:00        如通过 → latest；不通过 → 修一轮或回滚
```

## 4. 两台机器的分工（并行，不撞文件）

```
A 机（无 DSH，写代码）：S1/S2/S3 的实现 + 单元/静态门禁
B 机（有 DSH，验证+发布）：真机安装验证、真实模型往返、发版与回滚

文件级约定：
  · A 机负责 lib/**、src/**、test/** 的实现
  · B 机负责 docs/**、发布脚本、在线验证；除非明确交接，不碰实现文件
```

## 5. 发布门（latest 之前必须满足）

```
① 全量门禁：build 0 / run-audit 0 失败 / 功能 verify 全绿 / entry-load 通过
② 真机：安装 → 重启 DSH → 能进界面 → 面板能打开 → 功能能点
③ 回滚点：npm 上有 stable-<上一版> 标签，发布说明写回滚命令
④ 任一不满足 ⇒ 只发 next，不动 latest
```

## 6. 回滚（30 秒）

```
npm dist-tag add dsh-folia@<stable> latest
用户：插件管理 → 安装/更新 → 重启
```

## 7. 当天没做完怎么办

```
· 把未完成部分降级为"默认关闭 + 隐藏入口"，已完成的照常发
· 不带着"红色仓库/崩溃风险"过夜
· 第二天从 PROGRESS 的下一行接着做，不重新设计
```
