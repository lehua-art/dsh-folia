## 1. 目标与边界

本次解决两类相关问题：玻璃接管不完整造成背景突兀，以及接管过程改变层叠上下文（Stacking Context）或包含块，导致其他插件窗口被遮挡、固定定位偏移。

已确认的默认策略：已知宿主面与经过验证的适配器完整接管；未知插件保留自己的内部背景和控件语义。不以全局清底、提高手工层级、改文字主题掩盖兼容问题。

成功标准：

- 同一区域有明确的背景与模糊绘制者，不因嵌套布局重复铺底或重复模糊。
- WE 的装饰、拉绳和自动提示不盖住其他插件的模态窗口；WE 不使原本能跨区域显示的第三方窗口被困在侧栏。
- 开启、逐面回退、皮肤让路、关闭和卸载都有成对的清理路径。
- 深浅主题、侧栏开合、拖拽缩放、滚动、动态挂载和弹层交互均有浏览器证据。

不包含：改字体系统、媒体解码、转码、桌宠协议、操作系统原生窗口层序；也不宣称解决原生进程崩溃。不可穿透跨源 iframe 或封闭 Shadow DOM，不为不受控制的第三方任意层级提供绝对保证。

## 2. 调查结论

以下为重构前基线源码的调查记录，用于说明设计动机，不代表当前实现仍包含这些结构，也不等于已在当前运行 GUI 中复现全部症状：

| 位置 | 已核实事实 | 风险 |
|---|---|---|
| [左侧栏](../../src/styles-sidebar.js) | 为将负层伪元素圈入列内，给宿主列增加定位和 `z-index: 0` | 列内高层窗口不能跨过列外更高层的兄弟区域 |
| [设置窗](../../src/styles-chrome.js) | 改写整窗背景令牌，并在窗口本体设置 `backdrop-filter` | 内部任意插件继承半透明背景；后代的包含块和层叠关系可能改变 |
| [右栏与内容面](../../src/styles-sidebar.js) | 框架玻璃、内容底板与原有内部背景分别处理 | 背景所有权不统一，可能出现实底残留和重复合成 |
| [额外雾化](../../src/glass-extra.js) | 为用户选择器生成负层伪元素，但没有统一管理宿主背景和上下文 | 能补模糊，不代表能安全接管任意插件面 |
| [自有浮层](../../src/styles-quick.js) | 拉绳、抽屉、公告、预设引导各自使用固定高层级 | 非用户主动请求的提示可能盖过宿主模态窗口 |
| [现有合成守卫](../../test/verify-glass-compositing.mjs) | 以构建产物的静态解析为主 | 不能单独证明实际命中顺序、fixed 定位和焦点正确 |

用户提供的层级对照表是定位线索：其中的旧构建数字与「唯一例外」结论不直接作为现行契约。除了 `z-index`，还必须检查 `filter`、`backdrop-filter`、`transform`、`isolation`、`opacity`、`contain`、`will-change` 等属性。层叠上下文、包含块和背景采样边界是不同概念，需要分别测试。

本轮已精确撤回上一轮底色适配的五个文件改动，重建客户端，原有可读性守卫通过。此前壁纸、联动桥和 README 修改保留。

## 3. 方案取舍

| 方案 | 收益 | 代价 | 决定 |
|---|---|---|---|
| 延续选择器补丁 | 单次改动较少 | 每个新插件重复解决背景与层叠问题 | 不采用 |
| 全局强制透明并统一提层 | 短期看起来覆盖广 | 破坏按钮填充、状态色、原生控件和第三方窗口层序 | 不采用 |
| 统一表面解析、适配与生命周期 | 背景、模糊、层级和撤回可一起验证 | 要迁移现有绘制路径并补浏览器回归 | 采用，方向已确认 |

统一不意味着每个区域都用同一种 DOM 技巧。统一的是决策与生命周期；具体绘制必须尊重区域原有的上下文。

## 4. 表面模型

### 4.1 三个职责

1. **配置解析**：沿用共享设置真源，将全局值与 `glassMode` 的继承／独立配置解析成表面配方。不再让 UI 或单条兼容规则自行决定参数来源。
2. **适配描述**：声明稳定锚点、背景拥有者、允许清底的布局节点、内容边界、原有绘制载体及安全回退。只匹配锚点不充分，结构条件必须同时满足。
3. **运行管理**：负责发现、去重、挂载、更新、让路和清理，统一记录当前有效策略。绘制器只写本插件拥有的节点、属性和样式。

拟在浏览器源码中分离表面描述与生命周期模块，接入既有构建期内联，不引入框架、运行时打包器或新的产品依赖。实际模块名与扁平符号在实施计划中固定。

### 4.2 接管分级

| 类型 | 背景处理 | 交互与层级 |
|---|---|---|
| 已知宿主布局面 | 只清理适配器列出的布局背景，绘制一份基底 | 不为宿主内容祖先新增层叠或包含块 |
| 已知编辑器、终端、代码预览 | 显式适配内容画布；保留选区、光标、诊断和语法主题 | 不把内容容器当模糊载体，不改变编辑器内部定位 |
| 第三方显式接入面 | 按最小接入约定识别布局和保留区域 | 仍需通过结构检查和定位约束，不因为声明接入就允许破坏性修改 |
| 未知第三方设置面 | 保留内部背景、控件和状态色 | 仅处理已知外围；不对所有后代清底 |
| 无法安全处理的面 | 使用主题一致的非模糊底板；若背景接管也不安全则完整原生回退 | 明确记录回退原因，不留下半接管状态 |

背景处理与可见性绑定。侧栏收起、区域卸载或让路后不留矩形底板；同一个节点被多个适配器发现时只允许一个拥有者。

### 4.3 第三方接入约定

拟采用版本化的声明式属性，不要求第三方依赖 WE 全局对象：

```html
<section data-we-surface="v1">
  <div data-we-surface-layout>可由 WE 处理背景的布局区域</div>
  <div data-we-surface-preserve>保留原生背景和所有后代</div>
</section>
```

以上是待实施的新约定，不是现有宿主 API。`preserve` 优先于布局声明；嵌套声明不能跨越另一所有者；不接受脚本、任意 CSS 或可执行回调。WE 写入的内部标记与第三方声明分开，卸载时不能删除第三方自己提供的属性。

不自动进入 iframe、Shadow DOM，也不依据「颜色看起来像白色」就判定背景可删除。

## 5. 绘制与层级规则

### 5.1 背景与模糊

- 普通布局节点不再仅为容纳负层伪元素而增加 `z-index: 0` 或 `isolation: isolate`。
- 模糊优先落在原生已有的无交互衬底，或 WE 自己创建且不包含第三方内容的装饰叶节点上。不得在共享内容祖先上新增滤镜来换取视觉效果。
- 在没有安全本地载体的侧栏等页面区域，可使用根级壁纸上方的独立装饰底板，以目标矩形定位；该底板位于页面内容下方，只采样背景，不包裹、移动或重排宿主内容。
- 根级底板仅限不滚动穿透、可明确裁剪的页面区域，不作为任意弹层的通用方案。坐标或遮挡关系无法可靠跟踪时退回非模糊底板。
- 已有模态上下文内的内容面只使用该模态边界内的安全载体，不将其底板放到全页前景层。不覆写宿主已有的遮罩、焦点陷阱和关闭顺序。
- `pointer-events: none` 是装饰层的必要条件，但不代表视觉上不会遮挡；绘制顺序仍须验证。内容透明度不能通过对整个容器设置 `opacity` 实现。
- 同一表面最多一份基础模糊载体。原生已负责模糊的遮罩不再叠加 WE 的第二份遮罩滤镜。

根级底板的更新采用观察目标尺寸及布局变化、滚动事件合并到单次帧更新的方式。静止时不持续轮询；隐藏时停止，销毁时解除所有观察器。没有可靠定位能力的环境不勉强开启该路径。

### 5.2 不以数字竞赛修层级

层级原则是「所属上下文正确，再谈局部顺序」，而不是递增 `z-index`：

| 元素 | 归属原则 |
|---|---|
| 壁纸、暗化、特效 | 留在背景层，不改变宿主内容树的层叠结构 |
| 玻璃底板 | 位于对应内容下，不进入模态或通知的前景层 |
| 拉绳、快速抽屉 | 按宿主停靠区域的已验证层级接入；外部模态打开时停用前景交互，避免压住或穿透模态 |
| 更新公告、首次引导 | 改为所属面内提示，或在外部模态关闭后展示；不以高层级强制盖住其他插件 |
| 用户主动打开的 WE 模态 | 优先沿用经核实的宿主模态契约；若没有可调用的公共 API，按原生模态根结构与层级接入，不假设存在全局弹层服务 |
| 其他插件的窗口 | 不改其 `z-index`，不把其节点搬到 `body`，不调用原生顶层 API 替其或为 WE 抢层 |

只集中管理 WE 自有浮层的语义层级与展示条件，不尝试接管整个应用的窗口管理。不能仅凭任意 `[role="dialog"]` 的存在就压制全部 WE UI；判定需要可见性、模态语义和所属区域，并有明确例外与测试。

保留第三方原本就存在的层叠关系。若第三方在未启用 WE 时自身已被困住，作为独立兼容问题记录，不通过修改宿主或第三方树来掩盖。

### 5.3 可撤销性

维护 WE 所有权记录，不批量清空宿主的 `style`。运行时确需改行内属性时，记录原值与优先级，仅当当前值仍由 WE 拥有时恢复；第三方在接管期间做出的新修改不能被旧快照覆盖。

停止、热重载和皮肤让路后应删除 WE 装饰节点、运行时样式、监听器及内部标记。主题切换不需要拆装编辑器或重建第三方组件。

## 6. 设置与迁移

- 保留现有全局玻璃值、逐面参数、继承／独立配置及其存储键，不创建第二份平行设置真源。
- 逐面的渲染策略独立于取值来源。新增策略键 `glassSurfacePolicy`，值为按稳定表面 ID 索引的 `auto`／`native` 映射；缺省为 `auto`。`native` 撤销该面背景、模糊与有关令牌接管，而不改写它保存的玻璃参数。
- 新键由共享 schema 定义校验、默认、导入导出和预设行为；首期不新增全应用四态总开关，不与既有共存目标混成同一次交付。
- 取消向未知设置子树泛化传播半透明背景令牌。已知布局通过适配器处理；控件填充与前景令牌保持成对，不把主按钮背景当作布局背景清除。
- `extraGlassSelectors` 保留其受限选择器输入与已有存储语义，但接入统一安全判定。不能安全创建模糊载体时明确回退，不再隐含承诺任意选择器都能玻璃化。
- 兼容信息放入高级设置，以可展开的状态列表显示表面、适配器和回退原因；不常驻遮盖内容，不保存聊天或编辑器文本。新文案走既有中英词表。
- 现有软件渲染回退、皮肤让路和插件启停仍然生效。旧规则在对应适配器迁移完成后退役，避免新旧两套同时绘制。

## 7. 首期覆盖与实施顺序

首期不是仅修一个设置页面，覆盖设置窗、官方左右栏、已知编辑／预览内容面及 WE 自有浮层。聊天、代码块和输入框的既有内容语义与可读性目标保留；涉及共享令牌与模糊载体的部分也须随新约束复核，不能留下第二条绕过层级规则的路径。

| 阶段 | 交付 | 前置 |
|---|---|---|
| 行为基线 | 最小第三方窗口夹具、背景拥有者夹具、实际构建产物载入与红灯 | 设计批准 |
| 表面内核 | 配方解析、适配优先级、策略、生命周期、原生回退 | 红灯证据 |
| 迁移接管 | 左右栏与设置窗，随后内容面、额外选择器和自有浮层 | 内核行为通过 |
| 浏览器验收 | 命中、焦点、定位、动态挂载、深浅主题与多宽度 | 接管迁移 |
| 独立复核与集成 | 真实差异审查、旧功能回归、文档与发布面检查 | 验收通过 |

实施范围预计涉及现有玻璃解析、样式模块、客户端生命周期、共享 schema、面板与词表、构建清单以及对应测试。非关联的媒体和联动桥改动保留，不做顺手重构。具体路径与验证命令将在批准后的任务契约中从仓库实际情况固定。

## 8. 验收标准

### 8.1 必须先失败的回归

1. 在侧栏插槽内挂一个固定定位的第三方模态，层级沿用原生模态；列外放置输入区。启用左栏玻璃后，原实现应能稳定暴露上下文围栏问题。修复后，模态遮罩、内容与关闭按钮都可命中，底层输入区不能抢点击。
2. 同一第三方弹层分别挂在侧栏子树、设置窗子树及根级 portal，验证滚动、侧栏宽度变化前后 fixed 相对位置没有因 WE 变化。
3. 用只含多层布局背景的已知设置面验证只绘制一份基底；加入主按钮、警告条、代码块、原生下拉框和显式保留区，验证其填充、选区和焦点仍存在。
4. 在未知插件面放入硬编码背景和自绘控件，验证 WE 不强制清理；切换逐面原生模式后，不残留 WE 底板和背景令牌。
5. 外部模态打开时触发 WE 更新公告、引导、拉绳和快速抽屉，验证装饰与自动提示不会覆盖其内容或拦截其点击。

### 8.2 浏览器矩阵

采用隔离浏览器和夹具，不修改当前 GUI 或活动 profile。验证实际注入的构建产物，不复制一份「理想 CSS」作为被测对象。

- 浅色／深色，静态／高对比背景；宽度覆盖桌面和 `320`、`375`、`414`、`768` CSS px。
- 侧栏展开／收起／拖拽缩放，编辑／预览切换，设置标签切换与多次挂载卸载。
- 单个模态、嵌套弹层、下拉、Tooltip、通知与先后打开顺序；原生 top layer 保持其浏览器行为，WE 不借此提升自己的装饰层。
- 有模糊／无模糊／软件回退，开启／逐面原生／皮肤让路／停用。
- `elementFromPoint`／`elementsFromPoint` 检查实际可点击目标；记录固定元素的矩形、焦点位置与关键祖先的计算样式；同时查看截图及背景像素变化。
- 不仅验证 `pointer-events`，还检查装饰像素没有盖住前景；用移除修复或种回旧围栏的负对照证明判据能失败。
- 多次开合后，WE 节点、监听器、观察器及待处理帧不累积；静止状态不持续全页扫描或逐帧读取布局。

首次通过夹具不等于所有真实插件已兼容。接近用户报告的真实插件需在独立测试 profile 中进一步联调；无法取得该插件或环境时明确列为未测，不冒充覆盖。

### 8.3 既有回归与交付门

在保留判据目标的前提下更新因架构迁移而锁死旧选择器形状的守卫，不以删除失败项换取通过。至少复跑现有玻璃合成、玻璃表面、额外玻璃、可读性、宿主绘制作用域和令牌契约守卫，以及客户端构建／同步、lint、typecheck 和全量 verify。

新增浏览器用例接入已有测试调度并执行负对照。新增策略覆盖 schema 校验、预设导入导出、旧配置读取、源文件与产物一致性。缺环境、浏览器未启动或平台分支跳过分别记账，不算通过。

上一轮全量验证的宿主 teardown 镜像复制权限问题，以及未能启动的独立审查尚未闭环。它们不会因本设计或新测试通过而自动消失；实施结束必须重新核验并如实报告。

完整实现需独立代码审查。现有团队运行器曾启动失败，不在本次顺便修改团队插件；批准实施后先检查原团队状态并采用可用的受控审查通道。没有独立结论不得声称已完成独立验收。

## 9. 审阅决定

本次请审阅的是以上整体设计：统一表面层、有限且明确的适配、背景与模糊分工、禁止新增宿主层叠围栏、自有浮层分级、逐面原生回退，以及行为优先的验收方式。

批准本稿后进入任务拆分与实施；批准不授权部署、提交、推送或修改活动 profile。若安全模糊与原有交互无法同时满足，优先保持交互与层级正确，明确回退，不静默提层。
